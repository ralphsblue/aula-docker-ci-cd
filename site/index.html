"Na minha máquina funciona" 🤷

O código roda no seu computador, mas quebra no do colega ou no servidor. O motivo quase sempre é o ambiente: versão diferente da linguagem, uma biblioteca faltando, outra configuração do sistema operacional.

A ideia do Docker é simples: em vez de entregar só o código, a gente entrega o código junto com o ambiente em que ele roda.

O que é Docker?

Docker é uma ferramenta para empacotar uma aplicação e tudo o que ela precisa (sistema base, bibliotecas, configurações) em uma imagem, e rodar essa imagem como um container isolado.

  • Docker CLI: o comando docker que você digita.
  • Docker daemon: o serviço que de fato cria e roda os containers.
  • Registry: onde as imagens ficam guardadas (Docker Hub, GHCR).

VM vs container

Máquina virtual

  • Emula um computador inteiro, com o próprio kernel.
  • Pesada: ocupa GBs e leva minutos para ligar.
  • Isolamento muito forte.

Container

  • Compartilha o kernel do host (namespaces + cgroups).
  • Leve: ocupa MBs e sobe em segundos.
  • Isolamento suficiente para a maioria das aplicações.

Imagem vs container

A imagem é a receita congelada: só leitura, feita de camadas. O container é a imagem rodando, com uma camada de escrita por cima.

Imagem está para container assim como classe está para objeto: de uma imagem você cria quantos containers quiser.

Dockerfile → Imagem → Registry → Container

Dockerfile

É o arquivo de texto com a receita da imagem. Cada instrução gera uma camada, e o Docker reaproveita (cache) as camadas que não mudaram. 

# imagem base
FROM nginx:1.30.7-alpine

# copia os arquivos do site para dentro da imagem
COPY site/ /usr/share/nginx/html/

# porta usada pelo container
EXPOSE 80

Dica: coloque no fim o que muda com mais frequência, assim o cache aproveita as camadas de cima.

Docker Compose

Quando a aplicação tem mais de um container (site, banco, proxy...), o Compose descreve tudo em um arquivo docker-compose.yml e sobe o conjunto com um único comando. 

services:
  site:
    build: .
    ports:
      - "8080:80"

CI/CD

CI - Integração Contínua

A cada push ou pull request, um robô valida o código, builda a imagem e roda os testes. Quebrou? Você fica sabendo na hora.

CD - Entrega Contínua

Passou no CI? O robô publica a imagem no registry e atualiza o servidor sozinho. Sem SSH manual.

git push → CI ✅ → Imagem no GHCR → Site no ar

docker imagesLista as imagens locais
docker logs <container>Mostra os logs de um container
docker exec -it <container> shAbre um terminal dentro do container
